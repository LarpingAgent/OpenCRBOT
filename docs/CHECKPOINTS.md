# OpenCRBOT checkpoints

เป้าหมายคือให้ OpenCRBOT อ่านหน้าจอ GPGPC ได้ ส่งข้อมูลให้ ClashAI เป็น policy หลัก เปรียบเทียบกับ FirstLight_CR แนะนำแบบสด และผ่านการเล่นหนึ่งแมตช์ใน Training Camp พร้อมยืนยันผล แต่ละ checkpoint ต้องมีหลักฐานก่อนขยับไปเปิดความสามารถถัดไป

## กติกาอัปเดตหลังจบ workflow

เมื่อ workflow ที่เกี่ยวกับ OpenCRBOT จบ ให้ปรับ checkpoint ที่เกี่ยวข้องในไฟล์นี้ทันที ก่อนเริ่มงานถัดไป โดยบันทึกสถานะล่าสุด, สิ่งที่ทำ, ผลที่วัดได้, พาธหลักฐาน, ข้อจำกัดหรือ blocker และ next step ที่ทำต่อได้. ถ้า workflow ไม่ได้เปลี่ยนผล ให้ระบุด้วยว่าได้ตรวจแล้วและเหตุใดสถานะจึงคงเดิม; ห้ามเลื่อนสถานะเป็นผ่านเพียงเพราะเพิ่มโค้ดหรือรันงานสำเร็จ.

ถ้าผลกระทบ roadmap หรือ handoff ให้ปรับ `docs/ROADMAP.md` และ `docs/PROJECT_HANDOFF.md` ให้ตรงกันใน workflow เดียวกัน. ก่อนปิด workflow ให้ตรวจ diff และ `git diff --check`; เมื่อหลักฐานครบและเอกสารพร้อม ให้ commit และ push การเปลี่ยนแปลงของ workflow ขึ้น GitHub `origin/main` แล้วบันทึก commit หรือผล push ไว้ใน handoff/checkpoint ตามความเหมาะสม. หาก push ไม่สำเร็จ ให้ระบุสาเหตุและสถานะค้างไว้อย่างชัดเจน.

## CP3 — ใช้ ClashAI เป็น policy หลัก

**สถานะ: ยังไม่ผ่าน**

มี adapter แปลง observation เป็น ClashAI BoardState, wrapper สำหรับ S1 และ GenModel FV3 inference แบบไม่ส่ง action และ runner เปรียบเทียบ session แบบออฟไลน์แล้ว. Checkpoint IceBow เก่ายังใช้กับ GPGPC ไม่ได้เพราะไม่มี `archers`; checkpoint Training Camp generalist โหลดได้ครบเด็ค. เพิ่มเส้นทางส่ง `my_next` เมื่อ icon reader รู้ค่าแล้ว. Reader ทำได้ hand 64/64 และ Next 16/16 ใน HUD holdout 16 เฟรมจากสองแมตช์อิสระ; sample ยังเล็กและ policy output ยังไม่มี label ตรวจความถูกต้อง. Metrics จาก replay reconstruction ต่ำ จึงยังไม่เปิดคำแนะนำสด. Live adapter ส่งประวัติ own plays ที่ runner ยืนยัน transition แล้วให้ FV3 รอบถัดไป; opponent-play history ยังไม่มีใน screenshot path.

การเปรียบเทียบ offline บน 7 เฟรมที่ติดป้ายจาก attempt 2 ให้ Gen FV3 เลือก `play` ทั้ง 7 เฟรม (slot 0 และ cell 2287 ซ้ำ); defensive baseline ให้ `suggest` 4 และ `wait` 3. การรันนี้ใช้ sampled states โดยไม่มีประวัติ action ที่ติดตามได้และยังไม่มี label คุณภาพ action จึงยืนยันความถูกต้องเชิงกลยุทธ์ไม่ได้. รายงาน: `runs/cp2-attempt2-hud-expanded/clashai-comparison.json`.

รันซ้ำ full tracked CP3 capture ด้วย hand geometry เดิม, clock/rubble/card assets เดิม และเพิ่มเฉพาะ Next reader: 424 เฟรมถูก skip (306 battle inactive, 118 tower status unknown), 176 เฟรมประเมินได้ และ FV3 ให้ผล `play` 94 / `wait` 82. Reader รู้ค่า `my_next` 164/176 เฟรม; baseline เดิมได้ 35 suggestions / 141 waits และผล baseline ตรงกับรายงานก่อนหน้าครบ 600/600 เฟรม. Agreement ของ play/wait คือ 117/176: ทั้ง 35 baseline suggestions เป็นเฟรมที่ FV3 เลือก play และ FV3 เพิ่มอีก 59 plays ในเฟรมที่ baseline รอ. ตัวเลขนี้วัดเพียงพฤติกรรมคำแนะนำจากภาพ ไม่ได้บอกว่า 59 plays ถูกต้องหรือควรเล่น. Templates และ labels มาจาก CP3 match เดียวกัน; 18/18 manual checks จึงไม่ใช่ independent holdout. เพิ่ม holdout จากสอง matches รวม 16 เฟรม ซึ่ง reader รู้ Next 16/16 และ hand ถูก 64/64 ช่อง; sample ยังเล็กและไม่ได้วัด action quality จึงยังไม่ใช่ CP2/CP3 pass และยังไม่เปิด live hints.
หลักฐาน pilot: `runs/cp3-next-reader-pilot-baseline-geometry/next-card-cp3-pilot-evaluation.json`; analysis SHA-256 `94c480e95031d5ebd02cdcab62c8c06237eb4b01581de4e821e13085b318401b`, checkpoint SHA-256 `8fae9a846b1ab57432230c436ffa7a9e7ad17ce9e7a4185cfe92d48f4c689a95`.

ข้อมูล FirstLight IL_Replay ที่ดึงมาหนึ่ง part มี 5,000 records และ 384,275 public play/ability events; ตัวกรองเด็ค IceBow พบ 41 matches. Parquet ทั้ง 5,000 records ไม่มี frame/state snapshots ขณะที่ `pipeline.dataset_gen` ต้องใช้ replay JSON ที่มี `frames` และ `play_frames`; CSV จาก `hf_to_crawl` จึงนำเข้า trainer ตรง ๆ ไม่ได้

ตัวสร้าง replay-to-corpus ใน `tools/build_clashai_corpus.py` สร้าง FV3 corpus สำหรับ IceBow จาก public replay events 25 แมตช์ที่ simulator รับได้ จาก 41 tag เป้าหมาย. `ClashAI/pipeline.dataset_gen` สร้าง 6,987 rows (2,134 play, 4,853 wait), 25 เด็ค และ 308 held-out rows; แยก Evolution/Hero จาก deck suffix และ simulator status แล้ว. ปรับ dataset converter ให้รองรับ entity snapshots แบบ dict และใช้ embedded RoyaleSim Evolution catalog เมื่อ JSON แยกไม่มี.

ชุดนี้ยัง **ไม่ใช่หลักฐานเพียงพอสำหรับ deploy policy**: simulator ปฏิเสธ 16/41 replay เพราะ `not_enough_elixir` หรือ `out_of_territory`; 11/25 replay ที่บันทึกได้จบก่อน source plays ครบ; ข้าม ability event ที่ระบุผู้ใช้ไม่ชัด 56 ครั้ง; และ simulated crown result ไม่ตรงกับ source 4/25 แม้ value label จะใช้ crown จาก source. Observation เป็น state ที่จำลองจาก action events ไม่ใช่ frame จากเกมต้นฉบับ. Train pilot บน CPU 1 epoch แล้วได้ holdout `cell_tile_top1=0.019`, `card_top1=0.324`, `gate_bal_acc=0.500` (105 held-out play rows).

รัน IceBow Colab วันที่ 2026-11-21 (Asia/Bangkok) บน Tesla T4 สำเร็จครบ 20 epochs จาก scratch; เลือก checkpoint ที่ดีที่สุดที่ epoch 12 ด้วย `cell_tile_top1`. Held-out 308 rows (105 play rows) ได้ `cell_tile_top1=0.1333`, `card_top1=0.3810`, `joint_top1=0.0476`, `place_dist=7.105` ช่อง และ `value_acc=0.9481`. Checkpoint โหลดในเครื่องและ hash ตรงกับ manifest แล้ว; อย่างไรก็ตาม held-out เป็น state reconstruction จาก replay events ไม่ใช่ภาพ/state จริงของเกม. Checkpoint IceBow ไม่มี `archers` จึงใช้กับเด็ค Training Camp ไม่ได้.

## CP7 — เล่นครบแมตช์และตรวจผล

**สถานะ: ยังไม่ผ่าน**

เปลี่ยน CP7 Windows wrapper ให้เปิด `--track`; live watch ใช้ `class-stable.short-gap-reid.v2` และเขียน `tracker_id_policy`, `track_class_switches`, `track_reassociations` ลง log. แมตช์ CP3 เป็นผู้ใช้เล่นเองและหน้าผลขึ้น Winner พร้อมสามมงกุฎฝั่งผู้เล่น; เป็นหลักฐานของ capture-to-result verification เท่านั้น ไม่ใช่หลักฐานว่า bot เล่นแล้ว. ปัจจุบันเพิ่ม Windows action path แบบมีผู้ใช้ยืนยันทีละ action: แสดงภาพ preview, ต้องพิมพ์ `PLAY TRAINING CAMP`, จับภาพซ้ำและตรวจว่าคำแนะนำเดิมยังอยู่, ตรวจ battle/regulation clock/Next card/ไพ่/elixir/ตำแหน่ง/ขนาดหน้าต่าง/ความสด, คลิกไพ่และตำแหน่งเพียงครั้งเดียว, แล้วตรวจ hand-slot replacement กับ elixir drop.
